## 1 多媒体平台软件 {#s1}

多媒体平台软件也称多媒体创作工具，教材定义为能集成处理和统一管理文本、图形、图像、音频、视频、动画，并按用户需要生成多媒体应用系统的编辑工具。教材把它分为多媒体素材制作软件与多媒体制作软件两类：前者处理单项媒体素材，后者负责组织、集成素材并形成应用作品。教材举例包括 PowerPoint、Animate、Authorware、Director、ToolBook、方正奥思等；这些是书中列举的历史版本语境，不是当前产品推荐。

教材所述理想平台功能（PDF 第238页）：

1. 提供可视化、集成性的开发环境，支持鼠标单击、拖放、页面布局以及类似“所见即所得”的编辑；也具备选择、循环等流程控制，以及媒体空间分布、呈现顺序和动态输入/输出的编排控制。
2. 导入、导出不同格式的媒体文件，与其他媒体编辑软件交换素材。
3. 组织超文本、超媒体和多媒体数据；以节点和链接支持非线性检索与查询。
4. 支持多媒体数据或外部应用程序之间的链接，以扩展作品功能。

## 2 创作工具类型与易混概念 {#s2}

教材比较制作系统时，可从页面组织、事件控制、时间安排和脚本逻辑等角度建立检查表，再核对具体软件是否具备相应能力。本章正文没有提供完整的逐款分类依据，因此不从软件名称反推唯一类别。尤其要区分用于编辑图标文件的工具，与使用图标或事件表达制作逻辑的平台；二者讨论的是不同对象。

## 3 网络型多媒体作品 {#s3}

本节把网络作品说明为基于浏览器/服务器模式开发、可在互联网或局域网发布，并通过浏览器使用的作品。教材与传统作品比较时列出占用存储空间小、易于网上传输、易于共享等特点，并强调多种素材兼容与开放式增删修改。这里是书中的比较语境，不表示任意网站都必然比任意本地作品体积小。

| 教材列项 | 复习时怎样解释 |
| --- | --- |
| 共享性 | 多人通过网络访问同一作品 |
| 易用性 | 用浏览器提供相对统一的使用方式 |
| 交互性 | 人机交互及人与人之间的交流 |
| 开放性 | 不同用户按情境和需求选择浏览 |
| 方便性 | 便于管理内容、增删信息与调用资源 |

本章后续用网站制作落实这一概念：站点管理负责组织文件，网页文档承载页面内容，媒体与链接构成呈现和导航。

## 4 公式、条件与步骤 {#s4}

本章无计算公式。下列步骤按教材指定的软件版本归纳，未在本机逐步实测。

### 制作图标

教材以 IconCool Editor 为例，介绍图标尺寸、颜色深度、工具箱、图标显示区、编辑区、预览区和调色板。流程可概括为：

- 新建图标并设定尺寸、颜色；书中提到 Windows 默认图标为 32×32 像素，这是书中示例，不代表所有平台的当前规格。
- 用工具箱逐点绘制，或导入裁切为正方形的图片素材；照片宜选择主体清楚、细节不过密的局部。
- 利用编辑区和预览区检查小尺寸显示效果，必要时修改颜色、方向或加文字。
- 通过 Save As 保存；示例默认输出 ICO。教材还列举 CUR、ICL、BMP、GIF、JPEG、PNG 等格式及从 EXE/DLL/ICL 文件提取图标的功能。

### 自启动光盘制作

书中示例使用 AutoPlay Media Studio 6.0 汉化版：新建方案并选模板；设置方案标题、页面大小、图标和背景；按需添加音频、按钮并设置按钮文本与点击动作；通过预览检查结果；选择发布并生成 ISO 映像；再用 UltraISO 查看映像内容，或用虚拟光驱检查发布结果。此处的 ISO 是发布映像，制作映像与把映像写入实体光盘是两个环节。书中 UI 和格式支持仅按该版本示例理解。

### 光盘类型、刻录流程与注意事项

教材将刻录解释为向 CD-R、CD-RW、DVD-R、DVD-RW 等可刻录介质写入数据，并以 Nero 9 的数据光盘流程为例：

1. 启动刻录程序，选择数据光盘类型和对应盘片。
2. 添加待刻录文件，检查总数据量未超过所选盘片容量。
3. 选择刻录机，设置盘名、写入速度和写入方式。
4. 开始写入，等待完成提示。

教材列出的注意事项是：刻录时尽量不运行其他程序；关闭书中所述电源管理待机设置；先用较低速度试刻并观察稳定性；刻录前先做模拟测试；避免连续刻录多张。书中给出的具体倍速档位和 Windows 电源管理菜单属于其年代示例，不应作为当前设备的通用速度建议或现行设置路径。

### Dreamweaver 2020 网页工作流

本章把网络型多媒体应用系统作为网站来制作。结合章节步骤，可按以下顺序复习：

1. **查看界面并规划站点**：认识应用程序栏、文档工具栏、文档窗口、属性面板和面板组；先规划网站页面、功能和文件结构（PDF 第257至261页）。
2. **创建、管理站点**：通过向导或高级模式定义本地站点，选定本地根文件夹；打开、管理站点，并在文件面板中创建、管理站点文件（PDF 第261至264页）。
3. **建立和保存网页**：新建空白 HTML 文档或用模板创建；打开、保存文档并设置文档属性（PDF 第265至267页）。
4. **规划布局**：使用教材介绍的可视化辅助功能与表格安排页面元素（PDF 第268至272页）。表格布局是本书的教学示例，应放在本书版本边界内理解。
5. **插入媒体**：输入或导入文本、插入图像，并按书中示例插入 Animate/SWF 或 FLV 媒体（PDF 第273至281页）。SWF/FLV 操作只说明本书示例，不据此宣称当前浏览器支持。
6. **组织导航**：认识外部、电子邮件、页内等链接类别；区分绝对路径和相对路径，并通过属性面板、菜单或“指向文件”方式创建超链接（PDF 第282至284页）。站点内部链接应结合根目录和文档位置检查路径是否正确。

### 站点与页面操作检查卡

| 对象 | 操作前要明确 | 完成后要检查 |
| --- | --- | --- |
| 本地站点 | 根文件夹和内容、资源的目录安排 | 站点文件能在管理面板定位 |
| 站点管理 | 新建、移动或改名的是哪个文件 | 页面引用的图片与链接仍有效 |
| 网页文档 | 新建、打开、属性与保存位置 | 保存后能重新打开并继续编辑 |
| 页面布局 | 标题、正文、导航和媒体的位置 | 内容层次；教材表格布局结果 |
| 媒体元素 | 文本、图像等来源及相对位置 | 素材路径、尺寸和预览结果 |

对于教材的 Animate/SWF、FLV 插入示例，先记录其版本工作流。若缺少运行支持，只能登记未验证，不能以页面上有文件名代替媒体播放通过。

### 超链接与路径辨析

链接类别关注“跳到哪里”，例如外部页面、电子邮件或页内位置；路径方式关注“从哪里解释地址”。绝对地址给出完整定位信息，相对路径须结合文档位置或站点根目录判断。作答时应同时说明链接目标和参照位置。

### 自编任务：把集成与交付分开验收

**版本与状态：** 图标按 IconCool Editor、自启动方案按 AutoPlay Media Studio 6.0、刻录按 Nero 9、站点按 Dreamweaver 2020 整理；均待对应环境实测。输入为自绘的场馆标记、自写说明和自行录制的短音频，保留素材原件。

| 任务 | 初始条件与操作 | 交付与检查 |
| --- | --- | --- |
| 图标 | 新建；设尺寸与颜色；绘制标记 | ICO；预览主体与边缘 |
| 本地菜单 | 新建方案；设标题、图标与按钮动作 | 工程；逐个预览入口 |
| 发布映像 | 从已检查的方案发布 | ISO；检查文件及引用 |
| 数据光盘 | 选介质；添加文件；核对容量与写入条件 | 盘片；独立读取和播放 |
| 网络站点 | 定义本地根目录；保存页面与资源 | 站点文件；逐页访问 |

映像任务与实体刻录分别记录。没有刻录机或适用介质时，刻录、读取与目标环境启动继续登记为待验证；不能从 ISO 已生成推定这些环节通过。图标的小尺寸预览也不能代替完整菜单或站点测试。

### 自编站点任务：移动页面后找回资源

建立下面的目录。目录树表示文件位置，文件名为本任务自拟；不复用原书存在疑点的路径例子。

```text
guide/
├── index.html
├── pages/
│   └── visit.html
└── assets/
    ├── sign.png
    └── intro.wav
```

1. 在 Dreamweaver 中定义 `guide/` 为本地站点根目录，新建并保存首页和参观页；登记站点、文档与文件面板各在管理什么。
2. 在首页输入标题和说明，安排导航与媒体位置；在参观页插入自绘图片，创建返回首页的链接。教材的可视化辅助和表格布局只按其版本练习。
3. 对 `pages/visit.html` 采用文档相对路径：图片是 `../assets/sign.png`，返回首页是 `../index.html`。先从当前目录退一级，再进入目标位置，逐段解释路径。
4. 将参观页移到 `pages/archive/visit.html`，重新检查引用。按移动后的文档位置，图片应为 `../../assets/sign.png`，首页应为 `../../index.html`；软件是否自动更新引用另记实际观察。
5. 关闭编辑预览，从站点入口逐页检查文字、图像和链接。音频文件存在、媒体已插入和实际播放是不同检查项；对书中 SWF/FLV 工作流，只记录其版本条件和实测状态。

记录包括软件版本、操作系统、素材来源、移动前后位置、预期路径、实际路径、预览结果与日期。依据成书第 8.7～8.12 节整理；相对路径答案是针对本任务目录逐级推算的结果。

## 本章小结

- 单项图像编辑与完整作品集成不同；平台选择需对应媒体编排、导航、交互与交付条件，不能由一个软件名字推定全部能力。
- 文档相对路径从当前页面所在目录解释，移动文件后应重新逐级核对资源位置；原书路径坏例继续保留疑点说明。
- 本地介质和网络作品都要在目标环境检查资源、入口与播放；ISO 映像生成、实际刻录和成功运行是不同验收事件。

## 自编练习

**1. 博物馆已有照片、旁白和动画，现在需要把它们组合成可交互导览。为何不能只挑一个图像处理软件就认为完成了平台选型？列出还要核查的组织能力。**

考点：第 1、2 节；层次：识记。

**答案：** 单一媒体编辑与多媒体作品组织的职责不同。导览平台还要能安排多种媒体、页面或场景、用户操作及播放控制，并支持编辑和交付。选型时应从作品结构和交互要求反推能力，不把软件曾出现在教材名单中当作已满足全部要求的依据。

**2. 准备把同一份导览内容分别交付为本地介质作品和网络型作品。设计两份检查单，比较素材组织、菜单导航和访问路径；不以光盘菜单能启动代替完整作品测试。**

考点：第 3、4 节；层次：识记、简单应用。

**答案：** 本地介质要核对素材完整性、菜单入口和目标环境中的启动与播放；网络型作品要核对站点组织、页面与媒体资源位置和超链接访问。两者都应检查内容和导航，不能以一个入口打开成功推断全部资源可用。刻录或发布后要在脱离制作目录的环境复测。

**3. 站点根目录含pages/exhibit.html与assets/logo.png。图片从exhibit.html引用时，使用相对于当前文档的路径应如何写？若把页面移入pages/archive/，为什么原路径可能失效？**

考点：第 4 节；层次：识记、简单应用。

**答案：** 原位置应写../assets/logo.png：从pages返回根目录再进入assets。页面移到pages/archive后，文档参照位置改变，原路径将指向pages/assets；按新位置应写../../assets/logo.png。这里明确采用文档相对路径，不混用站点根参照。

**4. 教材示例包含旧版制作工具、刻录流程和Animate媒体。团队没有相同运行环境，却想把“菜单存在、文件已生成”写成验收通过。应如何记录版本和验证结果？**

考点：第 4 节；层次：领会、简单应用。

**答案：** 按教材版本记录需要学习的制作流程，分别标明未在指定环境验证的操作和媒体播放条件。生成文件只能证明某一输出步骤发生，不能证明目标环境可启动、可播放或链接正确。验收应记录环境、操作、预期与实际结果；缺少运行验证的项目继续列为待验证。

**5. 图标在编辑区里细节清楚，但放入菜单后主体难辨。说明图标编辑、菜单集成和预览检查分别应观察什么；“ICO 已保存”能证明哪些步骤完成？**

考点：第 4 节；层次：识记、简单应用。

**答案：** 图标编辑应检查尺寸、颜色和构图，小尺寸预览检查主体与边缘是否可辨，菜单集成还要核查引用及实际显示。ICO 已保存只说明产生了相应文件，不能证明菜单引用正确或小尺寸效果合格。应调整自绘素材，重新保存并在菜单中复查。

**6. 一个制作方案已生成 ISO，但没有写入盘片，也没有在使用端运行。分别列出已完成、尚待验证的环节，以及下一步需要保存的观察记录。**

考点：第 4 节；层次：识记、领会、简单应用。

**答案：** 可以记录映像已生成，但仍要检查映像文件内容与素材引用；实体写入、盘片读取、目标环境启动和媒体播放没有由此完成。后续应登记刻录软件和设备、介质、容量检查、写入结果、读取情况及菜单与各媒体的实际表现，缺少条件的环节保持待验证。
