# R10：笔记细读、条件补全与阅读节奏

日期：2026-11-03。修改范围为两门课的 12 章笔记、两份课程导读，以及术语表、易错点清单，共 16 份课程 Markdown。完成 80 次定点编辑，包含回读和手机显示检查后的微调，不等于 80 个彼此独立的问题。另同步修正既有核验脚本中的两课共享表格文本。

## 主要不足与修订

本轮重点检查“解释能否顺着读”“章末总结是否保留正文条件”“读者能否追踪中间状态”。没有为缩短篇幅删除教材知识点，也没有重排章次或修改网站样式。

| 不足 | 原文表现 | 修订方式 |
| --- | --- | --- |
| 解释很长，但没有清楚区分评价目标 | 计组第 1 章习题 5 把三种算法说成“三个结论”，又把统一单位换算与改变权重混在一起 | 先用表格给出三种计算方式与两种选择结果，再说明实际总耗时和相对加速比回答不同问题；保留附录的不同方法 |
| 将带条件的规律写成通则 | “同步量的 P/V 写在同一进程里必错”“写使能互斥”“RAID 防单盘损坏” | 分别补回具体同步约束、数据通路条件与 RAID 级别；不把题型经验当成普遍规则 |
| 正文与复习总结互相抵触 | 正文说多个目的端可同时锁存，章末却说写使能互斥；正文允许按完整表项取整，章末却说必须整除 | 正文、总结和自测问题一起核对，避免读者只读速查时学到不同规则 |
| 过程挤在一句话中 | `counter++` 的三次交错操作，循环汇编的初始化、步长与条件，单缓冲/双缓冲的数据流转 | 交错过程改成状态表，循环分析拆成编号步骤，缓冲说明按输入、复制、处理分开叙述 |
| 结论缺少适用条件 | 多道批处理使平均周转时间必然变长；流水线必然延长单条指令延迟；阻塞时 CPU 必不空闲 | 改为根据作业组合、流水实现与就绪任务情况判断，并区分进程等待和硬件访存延迟 |
| 术语、公式或题设容易误读 | 移码最高位规则、单精度规格化公式、银行家向量比较、装入阶段的位置 | 在同一处补明偏置、阶码范围、逐项比较和构建/运行阶段的区别 |
| 叙述带有训诫或口号语气 | “整章的坏习惯只有一个”“谁的优势更硬”“最稳的手艺” | 用错误原因、判定条件或具体反例替代评价读者的措辞 |
| OCR 影响辨认 | 计组第 5 章习题 1 多个术语粘连；第 4 章“延迟时间损失片”；第 6 章“RAID 系统总线” | 补分隔标点；按教材正文改为“延迟损失时间片”；其余保留原有术语与次序 |

## 核对依据

- 计组习题 5 的三种方法与原数值：`资料/教材/计算机组成原理/book.md` 第 4948–4952 行附近的附录解答；正文性能综合讨论在第 935 行附近。本轮修正的是笔记额外扩写的推论，未删除附录给出的不同方法。
- 延迟损失时间片：同一本地教材第 3276–3278 行正文的定义及记号 C，用来核正章末习题中错置的字序。
- SPEC 官方 CPU 2017 概览：`https://www.spec.org/cpu2017/Docs/overview.html`，说明综合指标取各项比值的几何平均；本轮不将该基准测试方法推广为任何工作负载的最优选择。
- GCC 官方 Overall Options：`https://gcc.gnu.org/onlinedocs/gcc/Overall-Options.html`，区分预处理、编译、汇编和链接，链接产生可执行文件；装入属于后续执行准备。
- Linux 官方 DMA API HOWTO：`https://docs.kernel.org/core-api/dma-api-howto.html`，用于复核 DMA 与 CPU 缓存、平台一致性条件的区分。

以上外部页面已在本轮读取。其作用是核对涉及的机制，不用于更新教材年代的硬件参数。
