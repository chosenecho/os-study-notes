## 本章学习目标

这一章跟着一次 I/O 请求往下走：应用发出请求，设备分配拿到可用路径，缓冲抹平速度差，最后交给驱动、控制器和磁盘调度去执行。

## 1 I/O 系统、设备和控制器（1.1–1.3，识记）

微机里，CPU、主存和各类设备控制器挂在系统总线上打交道；到了大型主机系统，为了把 CPU 从繁琐的外设管理里彻底解放出来，还会在 CPU 与控制器之间再加一级 **I/O 通道**——通道本质上是一台能自己跑通道程序的小型专用处理器，能独立管好几台控制器的数据收发。

面对五花八门的外设，教材从三个维度做分类：

| 分类依据 | 类型 | 理解要点 |
| --- | --- | --- |
| 传输速率 | 低速、中速、高速 | 低速如键盘鼠标（每秒几字节到几百字节），高速如磁盘网卡 |
| 交换单位 | 字符设备、块设备 | 字符设备按字节流收发、不可寻址（如键盘打印机）；块设备按定长块读写、可随机寻址（如磁盘） |
| 共享属性 | 独占、共享、虚拟设备 | 一段时间内只归一个进程用（打印机）、允许并发交叉访问（磁盘），或靠 SPOOLing 把独占设备包装成共享逻辑设备 |

CPU 并不直接给机械马达或激光头发电信号，中间全靠硬件电路板——**设备控制器（I/O 接口）**当翻译官：接下 CPU 发来的命令和地址、控制外设干活、暂存中转数据、回报忙闲与出错状态并做差错校验。一块标准控制器内部切分三块（单选与简答高频点）：

- **设备控制器与 CPU 的接口**：摆着数据寄存器、控制／状态寄存器，靠数据线、地址线、控制线跟系统总线相连。
- **设备控制器与设备的接口**：接具体外设的数据、控制和状态信号线（一个控制器可挂一台或多台设备）。
- **I/O 逻辑**：整块板子的指挥中枢，里面最核心的两个部件是**指令译码器**（识别 CPU 发来的是读命令还是写命令）和**地址译码器**（比对地址总线上的设备号，确认是不是在喊自己）。

初学常把“设备控制器”和“设备驱动程序”叫混：控制器是插在主板或芯片里的**硬件电路**，驱动程序则是装在操作系统内核里专门指挥这块电路的**软件模块**；而刚才提过的通道，则是比单块 DMA 控制器更高级、能自己取通道指令跑复杂 I/O 链路的硬件部件。

## 2 三种 I/O 控制方式（2.1–2.3，领会）

同样是经控制器读写外设，CPU 到底要操多少心？按“怎么知道设备准备好了”和“谁亲自动手搬数据”这两条线，控制方式一步步把 CPU 解放出来：

| 方式 | CPU 如何得知就绪／结束 | 谁组织数据搬运 | 主要代价 |
| --- | --- | --- | --- |
| 轮询／程序查询 | CPU 跑死循环不断读状态寄存器 | CPU 自己执行 I/O 指令逐字／字节搬运 | 等外设期间 CPU 100% 陪着空转 |
| 中断驱动 | 外设就绪后主动发中断叫 CPU | CPU 在中断服务程序里搬运那个字／字节 | 省掉了空等，但每传一字就进出一次中断，高速块传输扛不住 |
| DMA（直接存储器访问） | 整块数据传完（或出错）才发一次中断报信 | **DMA 控制器**直接在设备与主存之间成块搬运 | 需添置 DMA 硬件，并在开始和结束时由 CPU 介入配置收尾 |

### 2.1 轮询与中断

**程序查询（轮询）**最原始：CPU 往控制器下达读命令后，原地循环读状态位，见“未就绪”就接着问，直到变成“就绪”才取走一个字，如此盯完整个请求。硬件最省，CPU 和外设却完全串行，慢速外设能把高速 CPU 拖垮。

**中断驱动**把“人盯设备”改成“设备喊人”：CPU 发完命令转头去跑别的就绪进程；等外设把一个字节或字攒进数据寄存器，主动拉高中断线，CPU 这才暂停手头工作进来把数据取走，取完立刻回去接着跑。低速字符设备（如敲键盘）用这招刚刚好；可要是换作读一块 4 KB 的磁盘扇区，按每 4 字节中断一次就得打断 CPU 上千次，光保护和恢复现场就把 CPU 累趴下了。

### 2.2 DMA 过程与寄存器

成块高速传输就得请 **DMA 控制器**上场了。CPU 只管“派活”和“验收”，中间整块搬运全归 DMA 控制器代劳：

1. **预处理（CPU 干）**：CPU 往 DMA 控制器里写好读／写命令、主存起始地址和本次要传的字节或字数，启动 DMA 后自己去跑别的进程。
2. **数据传送（DMA 干）**：外设每准备好一个字，DMA 控制器就向总线借一个存储周期，直接把数据推进（或读出）主存，同时自动把内存地址往后推、把剩余计数减 1，全程不打扰 CPU。
3. **后处理（CPU 干）**：计数器减到 0 整块传完（或中途报错），DMA 控制器向 CPU 发**一次**中断，CPU 进中断服务程序核对状态、唤醒等待数据的进程。

为了独立干完第 2 步，DMA 控制器内部必须配齐四类寄存器：

| 寄存器 | 教材名称 | 作用 |
| --- | --- | --- |
| CR | 命令／状态寄存器 | 存 CPU 下达的读写命令、控制位以及设备状态 |
| MAR | 内存地址寄存器 | 存当前要读写的主存地址，每传完一单位自动递增 |
| DC | 数据计数器 | 存本次还剩多少数据没传，每传完一单位自动递减 |
| DR | 数据寄存器 | 暂存设备与主存之间中转的那个字或字节 |

做单选时盯紧分寸：**DMA 并不是“全程零 CPU 干预”**，开头的寄存器初始化和结尾的中断收尾仍得靠 CPU；它省掉的是中间成百上千次逐字搬运的中断。另外，DMA 写主存的那一瞬间要跟 CPU 争用内存总线（周期挪用），但只卡纳秒级的一拍。

### 2.3 两种「等待」不是一回事（跨课程对照）

同时备考《计算机组成原理》的同学，读到这里常有一个错觉：操作系统说“进程阻塞等待 I/O，CPU 去干别的”，计组却说“DMA 周期挪用，CPU 被迫停摆”。两句话听起来都在讲“等 I/O”，其实是两个层面的事，混在一起会把整条 I/O 路径想拧。

| 比较 | 操作系统的“进程阻塞” | 计组的“DMA 周期挪用” |
| --- | --- | --- |
| 发生在哪一层 | 操作系统软件：内核把进程状态改为阻塞、挂入等待队列、切换栈与页表 | 硬件电路：DMA 控制器向总线仲裁器申请使用权 |
| 时间尺度 | 微秒到毫秒级（切换本身是微秒量级，等设备完成则可能更久） | 纳秒级（让出单个存储周期或一小段突发） |
| 此时 CPU 在干什么 | 主动转去运行另一个就绪进程，CPU 没闲着 | 被动停一个或几个存储周期，随后继续执行原指令 |
| 由谁发起 | 进程执行系统调用后条件未满足，或等待的事件尚未发生 | 外设控制器或 DMA 引擎发起总线请求 |
| 如何恢复 | 事件完成后唤醒进程，重新进入就绪队列，等调度程序选中 | 总线释放后 CPU 自动继续取指，不需要调度介入 |
| 程序能否察觉 | 程序员可见：涉及状态、队列、调度策略 | 对程序透明：指令流上看不出被打断过 |

一句话分开：**进程阻塞是“把 CPU 让给别人”，DMA 周期挪用是“CPU 暂时借不出总线”**。前者是软件主动的调度行为，后者是硬件被动的仲裁结果。一次 I/O 里两者可以同时发生，也可能只发生其中一个——轮询方式的 I/O 既不阻塞进程，也用不着 DMA。

三处口径差异，与《计算机组成原理》第 6 章「与《操作系统概论》的对照」那一小节对着看：

1. 分类：本课把异常算作中断的一类（同步中断，也称内部中断或异常），与异步中断并列在中断之下；计组把内部异常与外部中断并列为两类来源，不设统称。
2. 响应步数：本课单重中断按四步讲（关中断与保护断点、保护现场、查向量表、恢复现场并返回），计组只把前半段叫中断响应，三步止于转入服务程序入口。
3. 时间尺度：进程阻塞以微秒到毫秒计，DMA 周期挪用以纳秒计，同一段 I/O 里两个尺度并存，不能合并成一段时间来算。

## 3 缓冲管理（3.1–3.2，领会）

CPU 算得飞快，外设慢得像蜗牛，而且两头一次吞吐的数据粒度往往还对不上。在内存里划出一片**缓冲区**卡在中间当蓄水池，有四桩好处：缓和 CPU 与 I/O 设备间巨大的速度差；减少对 CPU 的中断频率；解决数据粒度不匹配；提高 CPU 与 I/O 设备之间的并行性。当然，蓄水池只能削峰填谷，要是上游常年灌水比下游排水快，池子再大迟早也会满。

### 3.1 单缓冲、双缓冲、循环缓冲

- **单缓冲**：内核只配一块系统缓冲区。输入时外设先把数据灌进这块缓冲区，再由内核拷进用户进程空间，拷完系统缓冲区立刻腾出来接下一块，进程则在自己屋里慢慢加工刚拿到的数据。
- **双缓冲（缓冲对换）**：配两块系统缓冲区轮换——外设往 A 块灌数据的时候，用户进程同时从已经装满的 B 块取数据，两边真正实现了并行流水；全双工双向收发也常靠双缓冲各管一头。
- **循环缓冲**：两块还应付不过来突发流量时，就把多块缓冲区首尾相接串成环。教材把环上的缓冲区标成三种颜色：**R**（空，等装数据）、**G**（已装满数据，等消费）、**C**（正被生产或消费占用），再配三个指针：`Nexti` 指下一个可用的空缓冲 R，`Nextg` 指下一个可取的满缓冲 G，`Current` 指当前正在读写的缓冲 C。

```text
生产者：调 Getbuf 领一块空 R 当 Current 写入 → 写完调 Releasebuf 改成满 G
消费者：调 Getbuf 领一块满 G 当 Current 读取 → 读完调 Releasebuf 改回空 R
```

追空或追满时照旧得阻塞等待：生产者追上消费者说明没空缓冲了，生产者等；消费者追上生产者说明没新数据了，消费者等。

### 3.2 公共缓冲池

给每台设备各修一套专用缓冲环太费内存，现代内核干脆修一座全系统共享的**公共缓冲池**，池里的缓冲区按当前身份挂进**三条队列**：空缓冲队列 `emq`、装满输入数据的输入队列 `inq`、装满待输出数据的输出队列 `outq`；工作时则临时扮演**四种角色**——收容输入 `hin`、提取输入 `sin`、收容输出 `hout`、提取输出 `sout`：

| 过程 | 从哪里取 | 做什么 | 放到哪里 |
| --- | --- | --- | --- |
| 收容输入 | `emq` | 外设把输入数据灌进 `hin` | `inq` |
| 提取输入 | `inq` | 进程从 `sin` 读走数据 | `emq` |
| 收容输出 | `emq` | 进程把待输出数据写进 `hout` | `outq` |
| 提取输出 | `outq` | 驱动把 `sout` 数据送交外设 | `emq` |

多进程并发摘挂这三条队列，正好把第 2 章信号量的手艺原封不动搬过来（见第 2 章）：给每条队列 `type` 配一个资源信号量 `RS[type]`（初值为该队列初始缓冲块数，只有 `emq` 初值为池总容量，其余两条为 0）和一个队列互斥信号量 `MS[type]`（初值均为 1）：

```text
Getbuf(type):
    P(RS[type])           // 先确认该队列有货（先资源）
    P(MS[type])           // 再锁住队列摘取（后互斥）
    b = 从该队列移除一个缓冲
    V(MS[type])
    return b

Putbuf(type, b):
    P(MS[type])
    把 b 插入该队列
    V(MS[type])
    V(RS[type])           // 挂好后通知等待者有货了
```

看 `Getbuf` 头两行的次序：雷打不动**先 `P(RS)` 等缓冲块、后 `P(MS)` 锁队列**。要是写反了，一旦某条队列为空，取块进程就会抱着队列锁 `MS` 睡死过去，后面想调 `Putbuf` 往里还块的进程连门都进不去，当场死锁。

## 4 设备分配与数据结构（4.1–4.2，领会、识记）

一个进程伸手要一台打印机或磁带机，光看那台设备本身闲不闲还不够——连接它的控制器甚至上游通道要是正被同一条线上的别的设备占着，数据照样过不去。内核为此用**四张逐级指向的控制表**把整条物理通路管起来：

| 表 | 全称 | 用途与关联 |
| --- | --- | --- |
| SDT | 系统设备表 | 全系统一张总表，每台物理设备占一栏，记着设备类型、标识符和指向其 DCT 的指针 |
| DCT | 设备控制表 | 每台设备一张，记设备忙闲状态、等待该设备的 PCB 队列，以及它挂在哪个控制器（COCT）下 |
| COCT | 控制器控制表 | 每个控制器一张，记控制器状态、等待控制器的队列，以及它连在哪个通道（CHCT）上 |
| CHCT | 通道控制表 | 每个通道一张，记通道忙闲状态、等待通道的队列及所辖控制器列表 |

带通道的系统分配一台设备，必须沿 `SDT → DCT → COCT → CHCT` 一路过三关：先查 DCT 看设备闲不闲（忙就挂上 DCT 等待队列），设备闲了再顺指针查 COCT 拿控制器（忙就挂 COCT 队列），最后查 CHCT 拿通道，整条通路全打通才能真正启动传输。当然，老式的“指名要某一台物理设备”太僵硬——要是 1 号打印机忙而 2 号打印机明明闲着，点名要 1 号的进程还得傻等；改成只报“设备类”让系统挑空闲同型机，就顺势引出了第 5 节的设备独立性。

做设备分配决策时，内核要兼顾三件事：**设备固有属性**（独占设备一段时间内只给一人，共享设备如磁盘可交叉服务，虚拟设备靠 SPOOLing 多人同享）、**分配算法**（先来先服务或高优先级优先，体现在阻塞队列怎么排）以及**分配安全性**：

- **安全分配方式**：进程每发出一次 I/O 请求就立刻阻塞自己，直到这次 I/O 彻底干完才醒来。既然占着设备的时候进程自己在睡觉，就绝无可能再去伸手要第二台设备，从根上掐断了死锁四条件里的“请求和保持”，代价是 CPU 计算与该进程自己的 I/O 没法并行。
- **不安全分配方式**：发完一个 I/O 请求进程照跑不误，跑着跑着还能继续申请别的设备。并发度高了，但一旦互相等设备就可能死锁，必须额外配齐安全性检查（对比第 3 章银行家算法动态试算安全序列的路数，见第 3 章）。

## 5 设备独立性（4.3，领会）

写 C 程序调 `printf` 或打开打印端口时，要是代码里写死了物理端口号或某台特定型号的硬件编号，明天机房换一台同款新打印机，所有程序都得重编译一遍。**设备独立性（设备无关性）**的本意就一句话：**应用程序只用逻辑设备名编程，跟具体物理设备解耦**。

连接两头的桥梁是内核维护的**逻辑设备表（LUT）**，每一项记着三栏：逻辑设备名、实际分到的物理设备名，以及对应的设备驱动程序入口地址。运行期系统按 LUT 把“逻辑打印机”映射到当下空闲的那台物理打印机——机房换新设备或做输出重定向（比如把原本送往屏幕的输出改存进磁盘文件）只需改映射表，上层应用一行代码都不用动。

这么一划界，内核里的 I/O 代码自然分成了两层：上头的**设备无关软件**包揽所有设备共通的活儿（逻辑到物理命名映射、权限检查、公共缓冲、块大小折算与空间分配、通用差错处理），底下的**设备驱动程序**只管把标准请求翻成某款特定控制器听得懂的寄存器读写动作。

## 6 SPOOLing 与共享打印（4.4，识记）

打印机是典型的慢速独占设备：甲在打一份百页报告，乙和丙难道只能干等着连提交都提不了？**SPOOLing（假脱机技术）**在多道程序环境下，借高速共享磁盘的一角把独占设备“虚拟”成大家都能随时提交的共享设备。整套班子由三大件组成：

- **输入井和输出井**：在**磁盘**上辟出的两片专用存储区，分别暂存从输入设备预收上来的批量数据和等待送往输出设备的成品文件（单选必考位置：**井在磁盘上，不在内存里！**）。
- **输入缓冲区和输出缓冲区**：在**内存**里辟出的中转站，用来垫平磁盘井与物理外设之间的瞬时速度差。
- **预输入进程和缓输出进程**：常驻后台的两个内核／系统服务进程，专门负责在物理外设与磁盘井之间搬运数据。

拿最经典的**共享打印机**走一遍：用户进程要打印时，SPOOLing 系统并不把真打印机分给它，而是在磁盘**输出井**里给它分一块空间，把待打印数据飞快地写进磁盘井，再生成一张打印请求表挂进假脱机打印队列，用户进程就算“打印完毕”、当场脱身干别的事去了；等真打印机一空下来，后台的**缓输出进程**就按队列顺序从输出井读出文件，经内存**输出缓冲区**喂给打印机一张张打完。在每个用户眼里，自己好像都独占着一台随叫随到的高速打印机——这就是把一台物理独占设备改造成多台逻辑虚拟设备的全过程。

## 7 I/O 软件层次与一次请求（4.5，识记）

把前面散落的模块从上往下摞齐，现代操作系统的 I/O 软件正好排成五层（连底层硬件共五层架构）：

| 层次（自上而下） | 主要职责 |
| --- | --- |
| 用户层 I/O 软件 | 运行在用户态，包括库函数接口、格式化输入输出（如 `printf`），以及 SPOOLing 假脱机守护进程 |
| 设备无关软件 | 统一命名与逻辑到物理设备映射、权限保护、缓冲管理、块设备空间分配、独占设备分配与公用差错处理 |
| 设备驱动程序 | 唯一认得具体控制器寄存器布局的一层：把抽象读写请求翻成控制器命令字、填好 DMA 参数并启动硬件 |
| 中断处理程序 | 外设干完活发中断时第一时间接手：保护现场、读控制器状态确认成败、唤醒阻塞在此次 I/O 上的进程 |
| 硬件 | 设备控制器、通道与物理外设实打实完成机械与电气传输 |

把一次“进程读磁盘文件块（未命中缓存）”沿着这五层上下走一个来回：用户进程调库函数陷入设备无关层 → 查缓存没命中，向下调磁盘驱动程序 → 驱动算好扇区命令写入磁盘控制器并启动 DMA，读进程自身挂起阻塞 → 磁盘寻道旋转把块经 DMA 搬进内存缓冲区，发完成中断 → **中断处理程序**上来核验无误、唤醒读进程回就绪队列 → 数据交回用户空间，等调度器再次选中该进程时继续往下跑。

顺手钉牢一个细节：中断处理程序唤醒阻塞进程，只负责把它挪回**就绪队列**；至于中断返回那一刻到底回原运行进程还是立马切给刚醒来的这个进程，还得看内核的抢占调度策略。

## 8 磁盘结构、格式化与访问时间（4.6，识记）

传统机械硬盘由一摞同轴高速旋转的圆形**盘片**组成：每个盘面划出一圈圈同心圆叫**磁道**，所有盘面上半径相同的磁道上下对齐围成一个空心圆筒叫**柱面**（同一个柱面上的磁道切换磁头不用挪动机械臂，所以文件系统总爱把连续数据优先塞在同一柱面内），每条磁道再切成若干等长弧段叫**扇区**（常见 $512\ \text{B}$ 或 $4\ \text{KB}$，是磁盘物理读写的最小单位；第 5 章讲的“簇”则是若干连续扇区的组合）。

一块裸盘买回来要存文件，得按顺序过三道工序：**低级（物理）格式化**给盘面划出磁道和扇区，填好扇区头尾的标识与 CRC/ECC 校验区；**分区**把整块物理盘切成 C 盘、D 盘这样彼此独立的逻辑卷（传统 MBR 分区表记在 0 磁道第 1 扇区的主引导记录里）；**高级（逻辑）格式化**才在每个分区里写入特定文件系统的引导块、空闲空间位图／FAT、i 结点表和初始空根目录。

磁头固定在每条磁道上的叫固定头磁盘（贵而罕见），日常全是所有磁道共用一个可伸缩磁头的**移动头磁盘**。移动头磁盘完成一次扇区读写，耗时由三段相加：

$$
\text{访问时间} = \text{寻道时间} + \text{旋转延迟} + \text{数据传输时间}
$$

1. **寻道时间**：机械磁头臂横移到目标磁道正上方的时间（通常是三项里的大头，几毫秒量级）。
2. **旋转延迟**：磁头到位后，干等盘片把目标扇区转到磁头底下的时间。假设扇区起始位置均匀随机分布，最快 0 圈、最慢整整 1 圈，**平均旋转延迟取转半圈的时间**。
3. **数据传输时间**：扇区划过磁头下方、真正读出或写入比特流的时间，一般只有零点几毫秒。

自编例：一块 $7200\ \text{r/min}$（转／分钟）的硬盘，每秒转 $7200 / 60 = 120$ 圈，转一整圈耗时 $1 / 120\ \text{s} \approx 8.333\ \text{ms}$，那么**平均旋转延迟就是半圈 $\approx 4.167\ \text{ms}$**；若已知平均寻道时间 $5\ \text{ms}$、单块传输耗时 $0.1\ \text{ms}$，读一块的平均总耗时就是 $5 + 4.167 + 0.1 = 9.267\ \text{ms}$（题干若另给控制器开销则再往上加）。一眼就能看出大头全耗在机械寻道和等盘片转圈上，这也是为什么连续大块读写远比零碎随机读写划算。

## 9 磁盘调度（4.7，领会）

当好几个进程同时阻塞在读盘上、请求队列里攒了一串不同磁道号时，先伺候哪一个？既然寻道时间是最大头，磁盘调度的核心算盘就是少让磁头来回折返跑（注意这里的 FCFS 等名字虽跟第 3 章进程调度重名，优化的却是物理磁道距离，见第 3 章）：

| 算法 | 服务规则 | 关注点 |
| --- | --- | --- |
| FCFS 先来先服务 | 按请求到达先后老实跑 | 最公平，但磁头可能在盘面两头疯狂拉锯，平均寻道极长 |
| SSTF 最短寻道时间优先 | 每次挑离当前磁头所在磁道最近的请求 | 贪心省路程；但磁头若一直被附近新来的请求粘住，边缘磁道请求可能长期**饥饿** |
| SCAN 扫描（电梯算法） | 磁头沿一个方向一路扫过去顺道服务，撞端头再掉头反扫 | 消除了饥饿；刚扫过的身后磁道要等一个大来回，两头与中间等待不够均匀 |
| C-SCAN 循环扫描 | 只沿单向扫描服务，到端头后空跑跳回另一端起点同向再扫 | 把各磁道的等待时间拉平了；回程算不算移动距离要看清题设 |
| NStepSCAN（N 步扫描） | 把请求队列切成每段最多 $N$ 个的子队列，逐段内部跑 SCAN | 扫描期间新来的请求一律排进后面的子队列，彻底治住“磁头粘在原地不动” |
| FSCAN | 只设两条队列：当前扫描队列锁死跑 SCAN，期间新来的全进另一条等待队列 | 是 NStepSCAN 把分批粒度放大到“当前整批”的特例，一轮扫完再换队列 |

动笔做 SCAN 和 C-SCAN 计算题前，先把题干里两个开关圈出来：**初始移动方向**（往磁道号增大还是减小走）和**掉头边界**——教材标准 SCAN／C-SCAN 要一路走到盘面物理尽头（如 0 或 199）才折返，而工程改良版 LOOK／C-LOOK 扫到该方向最后一个实际请求就立刻掉头，两种口径算出来的总道数差出一大截。

### 9.1 自编完整例

磁道范围 0–199，磁头初始位于 50，等待队列按到达顺序为 `10、90、20、80`，本轮没有新请求。初始扫描方向为磁道号增大的方向。计算到最后一个请求完成为止，C-SCAN 的跨端返回计入移动距离。

| 算法 | 运动路径 | 总移动磁道数 | 每请求平均移动 |
| --- | --- | ---: | ---: |
| FCFS | 50→10→90→20→80 | 40+80+70+60=250 | 62.5 |
| SSTF | 50→20→10→80→90 | 30+10+70+10=120 | 30 |
| SCAN | 50→80→90→199→20→10 | 30+10+109+179+10=338 | 84.5 |
| C-SCAN | 50→80→90→199→0→10→20 | 30+10+109+199+10+10=368 | 92 |

若是题目注明“扫到该方向最远请求即折返”（即 LOOK／C-LOOK 口径），上面 SCAN 的路径就缩成 `50→80→90→20→10`，总移动降为 `120`；C-LOOK 缩成 `50→80→90→10→20`，总移动 `130`。顺便留意一个反直觉现象：在这组只有 4 个请求的静态短例子里，标准 SCAN 因为硬冲到了 199 边界，总道数（338）比傻跑的 FCFS（250）还多——别拿这个特例怀疑重负载下电梯算法的优势。

跑 SSTF 时每走完一步都要站在**新磁道**上重算剩余距离；万一左右两边各有一个请求离得一样近，先写明按“先来先服务”或题设规则破平局。本例第 1 步站在 50 看 `20` 和 `80` 都差 30 道，按到达先后（20 在 80 前）先去 20。

### 9.2 逐步累加：每一步的移动量摆出来

上面那张表只给总和，考场上要写的却是逐步过程。一步一行，累计量就是把上一行加上本行增量。

**SSTF**

| 步 | 当前磁道 | 选中请求 | 移动量 | 累计 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 50 | 20 | 30 | 30 |
| 2 | 20 | 10 | 10 | 40 |
| 3 | 10 | 80 | 70 | 110 |
| 4 | 80 | 90 | 10 | 120 |

**SCAN**（向磁道号增大方向扫，撞到 199 边界再反向）

| 步 | 当前磁道 | 动作 | 移动量 | 累计 |
| ---: | ---: | --- | ---: | ---: |
| 1 | 50 | 服务 80 | 30 | 30 |
| 2 | 80 | 服务 90 | 10 | 40 |
| 3 | 90 | 扫到边界 199 | 109 | 149 |
| 4 | 199 | 反向，服务 20 | 179 | 328 |
| 5 | 20 | 服务 10 | 10 | 338 |

**C-SCAN**（同向扫到 199，直接跳回 0 再继续）

| 步 | 当前磁道 | 动作 | 移动量 | 累计 |
| ---: | ---: | --- | ---: | ---: |
| 1 | 50 | 服务 80 | 30 | 30 |
| 2 | 80 | 服务 90 | 10 | 40 |
| 3 | 90 | 扫到边界 199 | 109 | 149 |
| 4 | 199 | 跳回 0 | 199 | 348 |
| 5 | 0 | 服务 10 | 10 | 358 |
| 6 | 10 | 服务 20 | 10 | 368 |

三张表对着看，差别就露出来了。SCAN 反向那一段从 199 一路走到 20，179 道；C-SCAN 回程同样 199 道，但途中一个请求都不服务，所以这些移动只换来更均匀的等待，而不是更多的服务量。题目若规定回程不计距离，C-SCAN 的总数要减掉 199，作答时必须先看题设这一句。

### 9.3 分批扫描的队列组织

SSTF、SCAN 甚至 C-SCAN 都有个隐患：要是进程源源不断往磁头脚下塞同一磁道的新请求，磁头就会被“钉”在原地寸步难行（磁臂粘着）。**NStepSCAN** 和 **FSCAN** 专治这个毛病：NStepSCAN 把长队切成每批最多 $N$ 个请求的小段，本段内部按 SCAN 跑完再领下一段，扫描中途新来的请求老老实实去后面批次排队；FSCAN 干脆只设两条队列，开扫那一刻已经在场的请求锁进当前活动队列一口气扫完，扫描期间新到的请求全归入另一条等待队列，等这一批清零再对调身份。做题时要是题干根本没给各个请求的到达时刻，默认就是静态一次性到齐，不用自己加戏拆队列。

## 10 提高磁盘访问速度（4.8，识记）

除了靠磁盘调度少走冤枉路，操作系统还用了五招从“少读盘、巧摆块、内存代劳”上给磁盘提速：

| 方法 | 原理 | 代价或边界 |
| --- | --- | --- |
| 提前读（预读） | 顺读文件时趁着磁头在场，顺手把紧挨着的下一块也读进内存 | 碰上随机乱跳的程序，预读进来的块没人用，白耗带宽和缓存 |
| 延迟写 | 改写过的盘块先标脏留在内存缓存里，等攒够一批或空闲时再合并写回；中途若又被改写就省掉了重复写盘 | 还没落盘前万一突然断电或死机，内存里的修改就会丢 |
| 优化物理块分布 | 把同一个文件或经常一起读的块尽量排在同一柱面或相邻磁道，扇区编号也可按旋转速度做交错排列 | 依赖文件系统的空间分配策略配合 |
| 虚拟盘（RAM Disk） | 划出一片真实内存装扮成块设备，安装文件系统当超高速临时盘使 | 读写是纯内存速度，但挤占宝贵主存，且默认断电即空 |
| 磁盘高速缓存（Disk Cache） | 在主存里留出一大片缓存区，专门存近期读写过的真实磁盘块副本 | 命中时零磁盘 I/O，但要操心脏块何时刷盘与一致性 |

最后把三组常混的名词拎清：**虚拟盘**本身就是主存假扮的独立盘（盘上内容在真硬盘上未必有对应物），而**磁盘高速缓存**存的是真硬盘上盘块的内存副本；至于前面第 3 节的**I/O 缓冲区**和这里的**高速缓存**，前者是上下游传数据时的临时中转站（用完即腾），后者则是为了赌局部性反复命中的副本仓库——尽管现代内核常让两者共用同一片页缓存内存。

## 12 教材本章习题

题目取自教材第 6 章“思考题与练习题”（共 9 题），答案取自教材附录“部分习题参考答案”（全部收录）。

### 12.1 单项选择题

**1. 关于 DMA 控制方式，下列说法正确的是【　】。**

A. 采用 DMA 控制方式时，CPU 不用干预整个输入/输出过程
B. 采用 DMA 控制方式时，每传输完一个数据块，CPU 要执行中断处理
C. 采用 DMA 传输方式，CPU 只在输入/输出开始和结束时干预输入/输出
D. 采用 DMA 传输方式只能提高传输速度，不能提高 CPU 与输入/输出设备的并行程度

**答案：C。** CPU 在传输开始前设置参数，结束时处理完成或出错，中间过程由 DMA 控制器组织。A 忽略了初始化与结束处理；B 把完成通知说成每块必做的中断处理；D 与事实相反，DMA 正因解放 CPU 才提高了并行程度。

**2. 关于 SPOOLing 系统的组成，下列说法正确的是【　】。**

A. 输入井和输出井都在内存中　B. 输出井和输出缓存都在硬盘中　C. 输入井和输入缓存都在硬盘中　D. 输入井和输出井都在硬盘中

**答案：D。** 输入井与输出井位于磁盘，用于暂存待处理与待输出的数据；输入缓存与输出缓存位于内存，用于在内存与设备之间中转。

**3. 设备控制器的 I/O 逻辑包含的主要部件是【　】。**

A. 仅指令译码器　B. 指令译码器和地址译码器　C. 仅地址译码器　D. 仅控制寄存器

**答案：B。** I/O 逻辑负责接收并解释 CPU 发来的命令与地址，因此需要指令（命令）译码和地址译码。前者区分命令种类，后者选定寄存器或设备。

### 12.3 简答题

**7. 说明设备控制器的结构和功能。**

答案：设备控制器由 CPU 接口、设备接口和 I/O 逻辑三部分组成。CPU 接口用于与主机交换命令、地址、数据和状态；设备接口连接具体设备；I/O 逻辑含指令译码与地址译码。控制器承担命令接收、地址识别、数据交换、状态报告及差错控制等功能。

**8. 说明 DMA 控制器的结构和控制方式。**

答案：DMA 控制器通过命令/状态寄存器 CR、内存地址寄存器 MAR、数据计数器 DC 和数据寄存器 DR 保存命令、目标地址、剩余数量及传输数据。CPU 初始化这些参数后，控制器直接在主存与设备之间组织成块传输，并在完成或出错时通知 CPU，通常以中断方式报告。

**9. 什么是设备驱动程序？**

答案：设备驱动程序是实现设备专用控制逻辑的软件模块。它接收上层请求，检查参数，把请求转换为控制器可执行的命令，配置寄存器并启动传输。完成状态的处理也有它参与，上层因此不必关心设备的具体硬件细节。
