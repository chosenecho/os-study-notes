## 第一批：标题、摘要与检测

### 先改入口页面

- 首页保留品牌名，增加课程学习主题。候选标题为「计算机课程笔记与交互练习 - studynote」；description 随课程注册信息维护，避免新增课程后仍称“两门课”。
- 在 `tools/mkdocs/content.py` 的课程入口处理中显式设置页面标题，例如「操作系统概论：课程笔记与复习指南」和「计算机组成原理：课程笔记与复习指南」。保留导航中的短标签“课程概览”，不为标题修改导航结构。
- 检查 MkDocs 与模板输出的最终 `title`、`og:title` 和正文主标题。标题只追加一次品牌名，名称与实际内容一致。章节页按主题自然补充课程语境，不把课程关键词堆进所有标题。
- 针对许可与第三方说明分别提供摘要；若由虚拟页面生成，在 `tools/mkdocs/licenses.py` 的元数据入口修复，避免修改构建产物。

Google 建议标题具有描述性、简洁且能区分页面；标题没有固定字符上限。[标题文档][google-titles]中的规则用于审核最终显示，不以英文字符数机械裁剪中文标题。

### 补充构建检查

在 `tools/checks/` 新增 SEO 产物检查，接到现有 `npm run check` 的严格构建之后。检测对象从本次产物与 Sitemap 读取，排除真实错误页。

- 检查正常页面的非空标题、课程入口标题唯一性、非空摘要、单一正确 canonical，以及意外 noindex。摘要重复先报告，再按页面用途判断。
- 检查 Sitemap 与正式域名、规范路径的一致性；不包含错误页、测试域名或重定向地址。
- 对正文标题与标题元素分别解析，不能把 H1 内的锚点符号当成第二个标题。
- 线上复核根域名跳转、正式页状态、错误页状态与缓存；本地文件检查不能替代 HTTP 检查。

第一批完成条件：已识别的课程入口重复标题消除；正常页面的元数据与 canonical 检查通过；正式路径、锚点和交互保持可用。

### 正文改进

- 保留既有大纲定位与稳定锚点。在相关小节开头直接解释概念，再给条件、推导和反例；已有解释能回答问题的，不重复新增“AI 摘要”。
- 公式说明紧邻符号定义、单位与成立条件；图示配文字解释。检查禁用 JavaScript 时，关键结论和公式含义仍可阅读，再决定是否需要额外的公式渲染工作。
- 练习页在操作区之外提供可阅读的自编输入、计算过程与结论。预设结果从现有模型核验，保证静态例子和交互输出一致。
- 概念以章节为主讲入口，术语表提供短定义与回查，实验页提供应用过程；补充正文上下文链接，避免复制同一整段解释。
- 在页面上说明教材或大纲的名称、版本和定位；可公开的参考链接需可访问、可追溯。真实维护者与纠错入口沿用项目已有身份，不虚构专家署名。修订日期对应实质内容变化。

执行 [内容贡献规则](../content-policy.md)：保持独立讲解与自编题，新增内容先审核再登记对应摘要，不为通过检查批量重算权利清单。

Google 对 AI Overviews 与 AI Mode 没有另加准入文件或专用标记要求，仍以可索引、可展示摘要和有用内容为基础。[官方指南][google-ai]支持先改善既有内容和技术基础。

### 搜索爬虫访问

现有 robots 使用通配放行，先检查是否与发布者意愿一致，再核对 WAF 是否阻断正常搜索抓取。不要为了 GEO 额外放宽全部安全规则。

搜索发现与模型训练分别处理。OpenAI 的 `OAI-SearchBot` 和 `GPTBot` 控制用途独立，训练爬虫放行不是搜索优化的通用前提。[OpenAI 爬虫文档][openai-bots]是具体配置依据。对其他平台先查各自当时的官方规则。

真实机器人可达性通过官方验证方法与访问日志判断；只改 User-Agent 后拿到 HTTP 200 不能证明真实爬虫已经抓取或收录。

## 第三批：结构化数据、日期与性能

- 先在浏览器中检查已有结构化数据，再决定是否在 `theme/main.html` 增补。首页优先考虑真实站点身份 `WebSite`；课程和章节按实际层级评估 `BreadcrumbList`；文章类型仅在正文、作者和日期均有依据时使用。
- JSON-LD 与可见内容、规范 URL 保持一致，使用模板安全序列化。检查语法与目标搜索功能资格，不能把通过验证当成一定展示或引用。
- 不把批量 FAQ、HowTo 标记列为默认工作；FAQ 内容是否需要增加，由学习者的问题决定。`llms.txt` 仅作为有明确消费方时的可选试验，不作为本轮交付前提。
- 检查 Sitemap 日期来源。若当前生成器使用构建时间，改为经维护的实质修订日期；无法可靠维护时省略。Google 要求 `lastmod` 准确反映重要更新，不应每次部署都把所有页面标成最新。[Sitemap 文档][google-sitemaps]
- 性能抽样覆盖首页、长章节、含公式页面和实验页，保存移动端与桌面端结果。只对测得的问题优化图片尺寸、公式资源、脚本执行和布局位移，保留主题原生能力。
- 真实用户数据可用时，按设备分组检查第 75 百分位的 LCP ≤ 2.5 秒、INP ≤ 200 毫秒、CLS ≤ 0.1。[Web Vitals 官方说明][web-vitals]是阈值来源；没有现场数据时标为缺测，Lighthouse 的实验室分数不替代现场 INP。

第三批完成条件：结构化数据与正文一致；日期不虚构；性能改动有前后对照；无阅读和交互回归。

## 效果记录与复核

站点维护者在具备管理权限时核对 Google Search Console 与 Bing Webmaster Tools 的验证、Sitemap 提交和索引报告。百度平台的可接入状态另行核对；没有后台数据时不把 `site:` 搜索命中数当成索引总量。

SEO 按页面与查询记录展现、点击、点击率、平均排名和索引状态，区分品牌词与课程问题。Google 的 AI 功能流量归入 Search Console 的整体 Web 搜索数据，不能从该报告直接得到跨平台 GEO 引用率。[Google 说明][google-ai]

GEO 采用上述试点问题，选能实际访问的联网问答平台，在相同语言和地区条件下重复测试。每次记录时间、平台、模型或模式、联网开关、完整问题、回答截图、引用 URL、是否指向本站及答案准确性。分别统计提及与带链接引用，记录分子、分母及失败请求，不把单次答案作为增长证明。

本项目拟在发布后按周人工复测，比较相同样本；本计划未创建定时任务。只报告观察到的变化，不把同时发生的增长直接归因于某一个标记或技能。
