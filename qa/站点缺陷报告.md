## 二、本地部署

按 README 的方式构建，`site_url` 显式指向生产域名，保证页面里的绝对地址与线上一致：

```powershell
# 仓库根目录
$env:SITE_URL='https://studynote.chosenecho.dpdns.org/'
python -m mkdocs build -f 站点/mkdocs.yml --strict    # exit 0，15 个 HTML，3.6 MB
python -m http.server 8123 --bind 127.0.0.1            # 工作目录：站点/dist
# 访问 http://127.0.0.1:8123/
```

构建环境：Python 3.12.10、mkdocs 1.6.1、mkdocs-material 9.7.7、pymdown-extensions 11.0.1（与 `站点/requirements.txt` 一致）。

**本地 = 线上的验证**（重要，保证后续结论对生产有效）：

| 对象 | 结论 |
|---|---|
| 15 个 HTML 页面 | 线上 = 本地 + 367 B Cloudflare beacon，剥离后逐字节相同 |
| `sitemap.xml`、`notes.css`、`interactions.js` 等 13 项静态资源 | 完全相同 |
| `search/search_index.json` | 相同，237 篇、93,678 字 |
| `robots.txt` | **不同**：线上是 Cloudflare 托管的内容信号文件（5,013 B），仓库里没有 |
| 404 | 线上返回主题化 404 页（HTTP 404）；本地 `http.server` 返回它自带的英文错误页——这是测试环境差异，不是站点缺陷 |

也就是说：下文凡是在本地测到的排版/交互问题，线上同样存在。

## 四、缺陷清单

### 4.1 P1（3 条）

#### P1-01 浅色主题、≥1024px 宽度下页头搜索入口不可见
- 现象：桌面/横屏平板上，页头搜索框常驻可见（234×48），但里面只剩一块浅灰底——占位文字「搜索」与放大镜图标都是白色，等于没有搜索入口。浅色是默认主题，覆盖了主要阅读场景。
- 量化（1440 宽浅色、未聚焦时）：占位文字计算色 `rgba(255,255,255,0.7)` 叠在 `rgb(243,244,246)` 上 ≈ **1.06:1**（WCAG 要求 4.5:1）；放大镜 `fill:rgb(255,255,255)` 对同底 **1.10:1**。深色主题同一元素 8.19:1 / 15.28:1，正常。
- 边界说明：**≤768px 时搜索收成图标，占位文字变成 `rgba(0,0,0,.54)`（约 4.4:1，可见但偏低）**，所以手机上不算"看不见"；问题只出在 ≥1024px 常驻搜索框的这套配色。1024/1220/1440 三档实测一致。
- 根因：`站点/docs/assets/notes.css:164` 只改了 `.md-search__form` 的背景（`--note-muted-surface`），没改 Material 用页头前景色（`--md-primary-bg-color` = 白）画的 placeholder 与图标。
- 修法：补 `.md-search__input::placeholder{color:var(--note-muted)}`、`.md-search__form .md-search__icon{color:var(--note-muted);fill:currentColor}`，或直接覆盖 `--md-primary-bg-color: var(--note-text)`。
- 证据：`qa/artifacts/lead/search-light.png`、`qa/artifacts/desktop/search-idle-light.png`

#### P1-02 手机上「点击放大」只放大 3%
- 现象：插图卡片右下角写着「点击放大」，点开后弹窗里的图和正文里几乎一样大，图内标注仍然看不清。
- 量化：iPhone SE 375 宽，正文图 **301px** → 弹窗图 **311px（1.03×）**；弹窗宽 353px（94vw），图片 CSS 宽 100%，且不可平移。原图 1000px，被压到 0.3×，图内约 10px 的标注实际只剩 3px。桌面同一张图 866px → 1312px（≈1.5×）正常。
- 根因：`notes.css:77` `width:min(94vw,1400px)` + `notes.css:79` `img{width:100%}`，手机屏上弹窗内容宽只比正文列宽多 10px；`interactions.js:201-207` 只换 `src`，没有缩放/平移逻辑。
- 修法：弹窗在窄屏用 `width:100vw`、`img{width:auto;min-width:min(1000px,150%)}` 并允许横向拖动，或按高度驱动（`max-height:76dvh;width:auto`），并放行 `touch-action:pinch-zoom`。
- 证据：`qa/artifacts/lead/verify-dialog-375.png`、`qa/artifacts/mobile/mob-02-dialog-375.png`

#### P1-03 计算机组成原理六章教材习题答案完全没折叠
- 现象：README 写「教材习题的答案默认折起来」。操作系统概论六章确实有 75 个「答案与解析」可折叠块；计算机组成原理六章 **0 个**，答案以表格第二列直接铺在页面上，自测时等于提前看答案。
- 量化：`<details class="exercise-answer">` 数量：操作系统概论 75（13/16/13/15/9/9），组成原理 **0**；组成原理六章共 33 行答案直接可见。
- 根因：`站点/hooks.py:28-34` 的 `format_exercises` 只识别 `**N.` / `**题目：` 形式的题号；组成原理的习题是 markdown 表格，正则 0 次匹配。`hooks.py:73` 对两门课用的是同一个函数，没有表格→折叠的转换分支。
- 修法：给 `format_exercises` 增加表格形态处理（把习题表拆成若干 `<details><summary>答案与解析</summary>`），或在 README/首页明确写「组成原理习题不折叠」。
- 证据：`qa/artifacts/functional/fn-01-co-exercise.png`、`qa/artifacts/functional/fn-01-os-exercise.png`

### 4.2 P2（16 条）

#### P2-01 宽表在手机上只能"盲滑"
- 现象：7 列的时间计算表在手机上只露出前 3 列，右侧没有滚动条、渐隐或箭头提示；滑到右边时首列已经不在视野里，不知道看的是哪个进程。
- 量化：chapter-3 的 7 列表 **702px**，滚动容器 343–375px → 初始隐藏 **359px（49%）**；实验页结果表 402px → 隐藏 91px。`.md-typeset__scrollwrap` 的滚动条占位高度 **0px**（触屏不可见），首列 `position: static`。数据本身可达（scrollLeft 0→91 生效），只是"看不出来能滑"。
- 根因：Material 的 `th{min-width:5rem}` 在 20px 根字号下 = 100px/列；`notes.css:111` 那条窄屏 `display:block;overflow-x:auto` 因特异性不足（0,1,1 < 0,2,1）是死代码；站点未加任何可发现性提示或首列固定。
- 修法：`.md-typeset__scrollwrap` 加右缘 `mask-image` 渐隐 + `scrollbar-width:thin`；宽表 `th:first-child,td:first-child{position:sticky;left:0;background:var(--note-surface)}`；更彻底是窄屏把 7 列表改成卡片堆叠。
- 证据：`qa/artifacts/mobile/mob-03-table-wide-375.png`、`qa/artifacts/mobile/mob-03-table-wide-scrolled-375.png`

#### P2-02 表格字号只有 12.8px（正文的 80%）
- 现象：表格里的中文比正文明显小，窄屏上逐字换行；1024 宽下出现"末行只剩一个字"的孤字。
- 量化：th/td **12.8px**（= Material `.64rem` × 20px 根字号），正文 16px；1024 宽出现 5 处孤字，同一张 11 行表高度从 540px 涨到 748px（+38.5%）。
- 根因：`notes.css:55` `.md-typeset table{font-size:.9em}` 特异性 0,1,1，被 Material `.md-typeset table:not([class]){font-size:.64rem}`（0,2,1）覆盖，作者想要的 14.4px 从未生效。
- 修法：写成 `.md-typeset table:not([class]){font-size:.9em}`（或 `.md-typeset .chapter-prose table`），窄屏再收 padding。
- 证据：`qa/artifacts/mobile/mob-04-table-font-375.png`、`qa/artifacts/tablet/tbl-table-co2-1024.png`

#### P2-03 标题层级塌陷：h1 与 h2 几乎同号，1920 下 h2 反超
- 现象：章节页主标题与「复习导航」等 h2 看起来一样大，页面靠字号分不出层级。
- 量化：h1 恒 **32px**、h2 **31px**（1280–1440），1920 档 h2 **34.1px > h1 32px**。
- 根因：`notes.css:49` 写的是 `h1#_top`，但构建出的 h1 是 `<h1 id="2">` / `<h1 id="_1">`，**匹配数 0**，clamp(1.85–2.65rem) 从未生效；h2 被 `notes.css:123` 固定成 `1.55rem`。
- 修法：选择器改成 `.md-typeset h1`，h2 降到 `1.3rem` 左右，保证 h1 > h2 > h3 > 正文。
- 证据：`qa/artifacts/desktop/table-1920.png`、`qa/artifacts/tablet/tbl-ipad-portrait-light-os2.png`

#### P2-04 章节之间的间距被清零
- 现象：31px 的大标题前只有 14–16px 空隙，章节之间没有分隔线，长文读起来所有小节连成一片。
- 量化：`chapter-2` 的 16 个 h2 中 **15 个**跟前文只有 14–16px；`margin-top:0`、`padding-top:0`、`border-top-width:0`；h3 最小间距 0px；页面总高 20,823px。
- 根因：`notes.css:53` 原本给了 `margin-top:2.8rem;padding-top:1rem;border-top:1px`，但 `notes.css:123` 用同选择器把它清零（后者在文件末尾，胜出），h3 的 `margin:0`（`:124`）同理。
- 修法：删掉 `:123-124` 里对 margin/padding/border 的归零，只保留字号微调。
- 证据：`qa/artifacts/desktop/h2-spacing-dark.png`

#### P2-05 字号选择只缩放正文，其余元素不跟
- 现象：把「字号」切到「大号」后只有段落变大，标题、表格、工具条、图注原地不动，20px 时表格只占正文 64%，层级被压平。
- 量化：正文 16 → 18 → 20px 生效且刷新后记住；表格恒 12.8px、h2 恒 31px、h3 恒 24px、工具条恒 17.5px、折叠摘要 14 → 17.5px（仍小于正文）。
- 根因：`interactions.js:131/139` 只写 `--note-font-size`，而 h2/h3 用 rem（`:123-124`）、表格来自 Material `.64rem`、工具条用 `.875rem`，都不乘这个变量。
- 修法：把 h2/h3/表格/图注改成相对正文的 em，或用 JS 同时驱动一个 `--note-scale` 让所有排版尺寸等比。
- 证据：`qa/artifacts/functional/fn-04-font-16.png`、`qa/artifacts/functional/fn-04-font-20.png`

#### P2-06 勾选「本章已复习」会让正文整体下移 40px
- 现象：点复选框后工具条里冒出一行「进度已保存在此浏览器」，工具条从 72px 撑到 112px，正在读的那段文字被往下推。
- 量化：72 → **112px**；正文章节首段 y 2028 → 2069，h2 顶 503 → 543，**位移 40–41px**；状态文字占 160×30px。
- 根因：`notes.css:61` 工具条是 `flex-wrap:wrap`，`.save-status` 只是普通 span，`.reading-size{margin-left:auto}`（`:64`）把它挤到第三行。
- 修法：`.study-toolbar{position:relative}` + `.save-status{position:absolute;right:1rem;bottom:.5rem}`，或改成 2 秒淡出的 toast。
- 证据：`qa/artifacts/mobile/mob-06-toolbar-before-375.png`、`...-after-375.png`

#### P2-07 插图弹窗不锁背景滚动，关闭后丢失阅读位置
- 现象：弹窗打开时上下滑，背景正文跟着滚；点关闭后已经不在原来那一段。
- 量化：弹窗打开状态下滚轮 700px，`window.scrollY` **5312 → 6012**（背景实际滚动 700px）；`body` 的 overflow 始终 visible。
- 根因：`interactions.js:201-207` 只调用 `dialog.showModal()`，没有锁 body；`notes.css` 也没有 `body:has(dialog[open]){overflow:hidden}`。
- 修法：打开/关闭时切换 `html.dialog-open{overflow:hidden}`，并给 dialog 加 `overscroll-behavior:contain`。
- 证据：`qa/artifacts/lead/verify-dialog-375.png`、`qa/artifacts/mobile/mob-08-dialog-scrolled-375.png`

#### P2-08 断点空档：960/1220 处正文列宽骤降，横屏比竖屏还窄
- 现象：平板/小笔记本宽度下正文忽宽忽窄；1024 横屏的正文比 820 竖屏还窄，左右留白一边 16px 一边 258px。
- 量化：959→960 正文 inner **927 → 686（−241px）**；1219→1220 **945 → 688（−257px）**；820 竖屏 inner 788（63 字/行）vs 1024 横屏 **750（54 字/行）**；1024 时左 16px / 右 258px。960–1219 区间左导航仍是抽屉、右侧目录已常驻。
- 根因：Material 在 60em(960px) 起显示右侧目录、76.25em(1220px) 才常驻左侧导航；`notes.css` 只有 40rem(640px) 一个断点，中间空档无人管；`--sl-content-width:56rem` 是 Starlight 残留变量（全站 0 处引用），真正生效的只有 `.md-grid{max-width:1480px}`。
- 修法：补 `@media (min-width:60em) and (max-width:76.234375em)` 段，给 `.md-content__inner` 设 `max-width:44rem;margin-inline:auto`、TOC 收窄到 10rem；正文上限用 Material 认的选择器而不是 `--sl-content-width`。
- 证据：`qa/artifacts/tablet/tbl-content-820-os2.png`、`.../tbl-ipad-landscape-light-os2.png`

#### P2-09 首页复习进度不显示「复习到第几章」
- 现象：首页只有「已复习 1/6 章」和进度条，看不出是哪一章，也没有「继续复习」入口。
- 量化：计数与进度条正常（勾两章后 1/6、1/6）；`[data-progress-chapter]` 徽标 **0 个**、`[data-next-chapter]` **0 个**——`interactions.js:161-180` 里对应逻辑永远不会执行（死代码）。
- 根因：`站点/docs/index.md` 只放了计数 span 与 `<progress>`，没放徽标和「继续复习」按钮；JS 早写好了，模板没跟上。
- 修法：二选一——在 `index.md` 六章列表项加 `data-progress-chapter`、补一个 `data-next-chapter` 按钮让现有 JS 生效；或删掉死代码并把 README 改成"显示已复习章数"。
- 证据：`qa/artifacts/functional/fn-07-home-progress.png`

#### P2-10 「正文之间可以互相跳转」没有落地
- 现象：12 个章节页正文里一个链接都没有（排除标题旁的 ¶ 永久链接），「见第 X 章 2.2」全是纯文本，只能靠侧栏/页脚跳转。
- 量化：12 个章节页正文内链 **0** 个；首页 15 个、实验页 0 个；全站 1064 个链接 0 断链（说明链接机制没问题，是内容没写链接）。
- 根因：源笔记 `课程/*/第N章_笔记.md` 正文没有 markdown 链接；`hooks.py` 也没有把「第 X 章 / 第 N 节」转链接的能力。
- 修法：改写源笔记里的交叉引用为 `[...](../chapter-X.md#锚点)`，或在 hooks 里做一次关键词→链接替换；不想做就把 README 的承诺改为「侧栏与页脚导航」。
- 证据：`qa/artifacts/functional/fn-03-chapter-no-inbody-links.png`

#### P2-11 深色主题下插图是整块白卡片
- 现象：夜间模式翻到插图页，每张图外面套着 96% 视口宽的纯白卡片，非常刺眼；放大弹窗里也是白底大图。
- 量化：`.figure-zoom` 计算背景 `rgb(255,255,255)`，页面 `rgb(24,25,29)`，对比 **17.56:1**；`chapter-2` 4/4 张、`chapter-1` 8 张全中；弹窗图片区 1312×481 纯白。
- 根因：`notes.css:74` `.figure-zoom{background:white}` 与 `:79` `.image-dialog img{background:white}` 硬编码，没有 slate 分支。
- 修法：容器改 `var(--note-surface)` 并保留 1px 边框，只给图片本身留白底；或深色下给插图加 `filter: invert(.92) hue-rotate(180deg)` 的对照方案（需评估图示颜色）。
- 证据：`qa/artifacts/desktop/figure-dark-1440.png`、`qa/artifacts/desktop/dialog-dark.png`

#### P2-12 第三章银行家算法题的资源表没渲染
- 现象：「12.4 简单应用：银行家算法」那道题的进程资源表变成一段带竖线的纯文本，题面数据挤在一行里。
- 量化：`站点/dist/chapters/chapter-3/index.html` 里出现原始 `|---|---|---|`；该题 `<table>` 数 **0**，纯文本段落约 120 字符。
- 根因：`hooks.py:22` 拼 `question + "\n" + prompt` 只留一个换行，`md_in_html` 要求块级元素前后有空行，表格因此没被解析；答案里的表格因为 `:24` 用了 `\n\n` 才正常。
- 修法：改成 `question + "\n\n" + prompt`，并在 `<section markdown="1">` 内的表格前后保证空行。
- 证据：`qa/artifacts/functional/fn-02-ch3-broken-table.png`

#### P2-13 首页空闲期就下载 437KB 搜索索引，弱网首屏被拖慢
- 现象：打开首页什么都不做，加载后约 1.3 秒就自动拉 `search/search_index.json`（437KB 解码）。
- 量化：解码 437,774B / 传输 **103,227B**，耗时 715ms，占首页总传输 191,200B 的 **54%**；Slow 3G 模拟下首屏 FCP **5,892–6,208ms**（3 个阻塞样式表、0 个 preload/preconnect）。
- 根因：Material 在空闲时预取搜索索引（站点未关）；站点也没做资源预加载提示。
- 修法：接受现状的话至少把首屏关键 CSS 预加载、`notes.css` 内联或合并；若要省流量可在 `mkdocs.yml` 关闭搜索预取（Material 无此开关，可考虑改 `search` 为按需加载的第三方方案），或把索引拆小（只索引标题+首段）。
- 证据：`qa/artifacts/delivery/weaknet.json`、`qa/artifacts/lead/live-idle.json`

#### P2-14 双斜杠 URL 返回 200 但页面完全崩掉
- 现象：`/lab/scheduling//`、`/chapters/chapter-1//` 都能打开，但样式/脚本路径按 `//` 解析成 `/lab/assets/...`，全部 404；logo 变成 1264×1264 的巨图填满首屏，正文被推到 8000px 以下，实验页表单不执行。
- 量化：`//` 路径 **HTTP 200**（无 301/308）；随后 5 个 CSS/JS **全部 404**；桌面 1280 宽下 logo SVG 渲染 1264×1264，h1 落在 8,282–9,154px。
- 根因：Cloudflare Worker 透传 `url.pathname`（`esa-deploy/worker/index.js:27`）给 Pages，Pages 未对重复斜杠做归一化；站内没有 `_redirects`。
- 修法：在 Pages/Worker 侧加 `_redirects` 规则把 `//` 301 到单斜杠，或在 Worker 里 `url.pathname.replace(/\/{2,}/g,'/')` 后再回源。
- 证据：`qa/artifacts/delivery/lab-double-slash.png`

#### P2-15 robots.txt 不受仓库控制，且封了百度
- 现象：站点没有自己的 `robots.txt`；线上返回的是 Cloudflare 的 5,013B 内容信号文件，没有 `Sitemap:` 行，且 `Disallow: /` 覆盖 `Baiduspider`。
- 量化：`https://studynote.chosenecho.dpdns.org/robots.txt` → 200，5,013B，无 `Sitemap:`，含 Baiduspider 的 Disallow；而 `sitemap.xml` 是正常的（2,110B，15 条 URL）。
- 根因：仓库里没有 `站点/docs/robots.txt`；Cloudflare 对该域名注入了托管版本。
- 修法：新增 `站点/docs/robots.txt`（`User-agent: *` / `Allow: /` / `Sitemap: https://studynote.chosenecho.dpdns.org/sitemap.xml`），并在 Cloudflare 侧确认不被覆盖。
- 证据：`qa/artifacts/delivery/live_robots.txt`、`qa/artifacts/delivery/net.json`

#### P2-16 甘特图段数一多就看不全，图上时间轴与数据对不上
- 现象：实验页默认 FCFS 只有 4 段，刚好铺满；切成 RR + 时间片 1 后有 11 段，时间轴只画到「P2 7–8」，后面 P1 8–9、P2 9–10、P4 10–11 完全看不见，滚动条也不显示（触屏上不可见），读者会以为周转时间只算到 8。
- 量化：11 段 ×(min-width 4rem=80px + 3px 间距) = **910px**，容器 674px（768 宽）/688px（1024）/626px（1220）→ 隐藏 **236 / 222 / 284px**；`.gantt` 的 `scrollbar-width:thin` 在触屏上不渲染，无渐隐/箭头提示。首屏 FCFS 4 段时 288/177/80/121 刚好铺满 674px，掩盖了这个问题。
- 根因：`notes.css:102-103` `.gantt{display:flex;overflow-x:auto}` + `.gantt-block{min-width:4rem}`（20px 根字号下 80px），既没有换行、也没有溢出提示。
- 修法：`@media (max-width:76.234375em){.gantt{flex-wrap:wrap}.gantt-block{min-width:3rem}}`，或给 `.gantt` 加右缘渐隐 +「横向滑动查看更多」提示，并把 `scrollbar-width` 改成 auto。
- 证据：`qa/artifacts/tablet/tbl-gantt-rr1-768.png`、`qa/artifacts/tablet/tbl-gantt-rr1-1220.png`
