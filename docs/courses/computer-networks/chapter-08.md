## 1 操作系统的职责与特征 {#s1}

操作系统协调计算机资源并为使用者和程序提供接口。处理机管理安排执行，存储器管理组织空间，设备管理协调 I/O，文件管理组织持久信息，接口管理提供使用途径。网络服务运行在这些基础能力之上，不能因为是服务器便不需要进程与存储管理。

并发描述任务在一段时间内交错推进，共享描述资源被多个活动使用，虚拟把物理资源抽象为逻辑对象，异步说明各活动受条件影响而以不预先固定的节奏推进。各类系统的组织方式可按下表辨认。

| 类型 | 主要组织方式 | 复习时要分清 |
| --- | --- | --- |
| 批处理 | 作业成批提交，由系统调度执行 | 多道作业可共享处理机，完成顺序未必等于提交顺序；交互较少 |
| 分时 | 多个终端共享系统，按时间片分配处理机 | 目标包括交互响应，不能把时间片理解为每个任务独占整台机器 |
| 实时 | 按时间或事件驱动任务，在规定时限内响应 | 判断是否满足时间约束，不能只看平均处理速度 |
| 微机 | 随微机能力发展，支持个人使用及更多任务和用户 | 关注开放性、通用性与硬件条件 |
| 分布式 | 多台计算机通过通信协同完成任务和资源管理 | 各节点与通信协作共同构成系统的工作过程 |

## 2 网络操作系统的分类与服务 {#s2}

网络操作系统把用户与网络资源联系起来，管理共享并提供通信和服务。按适用范围可分专用型与通用型；按结构可分对等与非对等。对等结构中各节点可兼顾本地任务与共享服务，非对等结构则更明确地区分服务器与工作站的职责。

服务范围包括文件共享、打印服务、数据库访问、节点通信、网络管理及 Internet 相关服务。服务名描述能力，不能据此判断每台节点都同时开放了这些功能。自编部署分析应先列资源在哪里、哪些用户访问、由谁认证和管理，再选择结构，而不是先把所有计算机都设置成共享服务器。

## 3 教材中的常见系统 {#s3}

| 系统 | 本章辨认线索 |
| --- | --- |
| UNIX | 多用户、多任务，具有权限管理、网络通信和文件等工具 |
| Linux | 类 UNIX 的多用户、多任务系统，支持网络协议与常见 UNIX 工具，源码开放 |
| NetWare | 以文件服务器和网络资源服务为核心，教材介绍服务器与工作站外壳分工及早期 IPX/SPX 环境 |
| Windows 系列 | 从局域网服务发展到集中管理、域服务与多种服务器角色 |

产品用途相近，不代表命令、目录和授权方式可以直接互换。

教材按 LAN Manager、Windows NT、Windows 2000、Windows Server 2003、Windows Server 2008 介绍演进。操作练习采用 Server 2008 的安装、账户和域服务环境。本节采用该版产品背景，后续界面名称也按它解释，供理解职责与过程；不把这份历史环境练习当成当前服务器选型或上线部署指南。

## 4 安装任务与方案核对 {#s4}

在 Server 2008 的教材环境中，先核对硬件兼容、磁盘空间、安装介质及原有系统和数据的处置，再选择安装方式。全新安装重新建立环境；升级安装考虑保留原配置与系统条件；通过部署服务的远程安装依赖网络引导等前提；Server Core 以精简的服务器组件和命令行管理方式为特点。

复习过程可按“确认条件—选择方式与版本—安装系统—初始配置—检查服务”的顺序组织。升级能否执行取决于具体版本与支持路径，不能把教材中的概述理解为任意旧系统都能直接升级。自编题若不给确切版本和路径，就只要求列核对步骤，不编造一个必定可行的升级命令。

## 5 本地账户、域账户与组 {#s5}

本地账户保存在相应计算机的本地安全数据库 SAM 中，域账户由域控制器上的目录服务集中管理。登录身份与访问权限有关，但“身份验证通过”不等于对所有资源有管理权。跨多台机器共享资源时，需要先辨认账户属于哪里。

用户组把具有共同授权需要的成员组织起来，便于一次分配一组权限；用户通过自己的账户登录，组本身不是一个可供多人共用密码登录的用户。一个账户可以属于多个组，分析时列成员关系与资源权限，不要把“在组中”当作所有操作均允许。

教材界面练习从“计算机管理”中的本地用户和组创建用户、设置有关账户选项，再创建组并添加成员。Administrator 与 Guest 是教材讨论的内置账户，使用时应结合各自角色与权限；练习设计不需要给出真实密码或让全体用户共同使用管理员账户。

## 6 活动目录、域与成员加入 {#s6}

Active Directory 保存用户、计算机、服务等对象及其属性。容器组织对象，OU 是域内用于组织和委派管理的单元，域是相应的逻辑管理单元，域树按连续命名关系组织多个域，林包含一棵或多棵域树。域控制器承担目录服务和认证等职责，成员服务器则可提供文件、邮件或 Web 等服务，二者不可等同。

站点用于表示物理网络连接关系；域是逻辑管理关系。一个域可以跨站点，站点也可以涉及多个域，所以不能把一栋楼、一条子网和一个域机械画成同一边界。这里采用成书对原书第 196 页的明确校注 LDAPv3；不使用“第 8 版”字样，也不把尚待核实的活动目录起始年份当成记忆结论。

按教材环境整理建立域的过程：

1. 准备符合要求的名称、TCP/IP 和 DNS 配置，以及用于 SYSVOL 的 NTFS 分区。
2. 在服务器管理器中添加 Active Directory 域服务角色，再运行相应目录安装配置向导；“已装角色”与“已完成域配置”是不同阶段。
3. 按任务选择新林或现有结构，设置域名、功能级别和相关域控制器选项，明确 DNS 安排。
4. 设置数据库、日志和 SYSVOL 位置及还原模式凭据，完成向导和所需重启。
5. 将成员机的 DNS 指向能够解析该域所需记录的服务器，再按域名和有权加入的账户完成成员加入，并验证域登录与目标资源权限。

检查时说明各条件怎样支持名称定位、目录存储、身份认证与授权。不能把“IP 能通”当成已满足域发现和加入条件。

## 本章小结

- 网络服务依赖处理机、内存、设备和文件等操作系统能力；对等/非对等结构按资源及服务分工辨认，不能只按机器数量分类。
- 本地账户在本机管理，域账户由目录服务管理；用户组汇总成员授权，不是多人共用的登录账户，认证成功也不代表拥有全部权限。
- 域描述逻辑管理，站点描述物理连接；加入域还须满足名称解析和目录配置。本章 Server 2008 操作属于教材历史环境，不能作为现行部署指南。

## 自编练习

**1. 服务器上同时运行文件服务和备份程序，偶有一个等待磁盘。用并发、共享和异步解释现象，并区分处理机管理与文件管理。**

考点：第 1 节；层次：识记。

**答案：** 两活动在同一时间段推进体现并发，共用磁盘等资源体现共享，等待条件使进展节奏变化体现异步。处理机管理安排执行机会，文件管理组织文件和访问；等待并不能单独说明系统已失去并发能力。

**2. 小组每台机器既处理本地任务也提供共享，另一方案集中到专用服务器。按结构怎样比较？再列三项可能由网络操作系统提供的服务。**

考点：第 2 节；层次：领会。

**答案：** 前者可按对等结构分析，后者更接近非对等服务器/工作站分工。服务可包括文件、打印、通信、数据库或管理等。比较应看共享范围、管理和认证责任，不能只凭机器数目判断结构。

**3. 把教材中的 UNIX、Linux、NetWare 与 Windows Server 2008 当作相同界面的四个名字，为何会影响复习？Server Core 又应与什么区分？**

考点：第 3、4 节；层次：识记、综合应用。

**答案：** 它们在系统组织、命令和管理环境上有差别，应抓各自特点。Server Core 是教材中一种精简安装与管理形态，不是把安装介质换成网络下载的同义词；全新、升级、远程安装描述的选择维度也需要分清。

**4. 一台保有资料的旧服务器准备改装教材环境。题设没给原系统版本与升级路径，能否直接承诺原地升级？请给出先做哪些核对。**

考点：第 4 节；层次：综合应用。

**答案：** 不能。先保全与核对资料、硬件兼容和空间，再查明确版本及升级支持条件，并确定介质、回退和验证安排。缺少路径条件时应列核对过程，而不是凭“升级”一词保证配置和数据都可原样保留。

**5. 三名资料员要访问同一共享目录，有人建议共用 Administrator 密码，并把“资料员组”直接作为登录账户。怎样改成可管理的设计？**

考点：第 5 节；层次：综合应用。

**答案：** 为每人保留可区分的用户账户，用组组织共同授权，再按任务配置共享和资源权限。组用于汇总成员与权限，不直接作为一个共用登录账户；也不需要因为访问同一目录而共享最高权限身份。

**6. 域控制器上已添加域服务角色，成员机用外部 DNS，管理员因 IP 可达便跳过目录配置。列出仍缺少的阶段，并区分域与站点。**

考点：第 5、6 节；层次：综合应用。

**答案：** 仍需完成目录/域配置、名称解析和存储等前提，核对成员 DNS、域名及加入权限，再验证域登录与资源授权。域描述逻辑管理，站点描述物理网络关系；IP 可达只证明一部分通信条件，不能替代域发现。
