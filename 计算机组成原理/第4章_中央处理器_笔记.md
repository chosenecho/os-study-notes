# 第4章 中央处理器

> 依据：2016年版教材第4章与大纲。[教材](教材/chapters/14_第4章%20中央处理器.md)。

## 考核目标

第3章规定了指令的功能，本章说明CPU如何通过数据传送、运算和控制实现这些功能。学习内容包括CPU组成、数据通路与定时、控制器，以及异常和中断。流水线部分要求能够划分流水段、计算吞吐率，并理解冒险产生的原因及其处理方法。

## 4.1 程序执行概述

CPU由数据通路和控制部件协同组成。数据通路保存、传送、加工数据；控制部件根据指令、时序及状态产生控制信号。取指、译码、操作数获取、执行、访存、写回等阶段不一定每条都做。

| 部件 | 职能 |
| --- | --- |
| PC | 后继取指地址 |
| IR与译码器 | 保存指令并解释字段 |
| 寄存器堆 | 通过读口和写口提供操作数及保存结果 |
| ALU | 运算、比较及有效地址计算 |
| MAR/MDR | 暂存主存地址和读写数据 |
| 控制器 | 决定选择信号、写使能、运算操作、读写请求 |

指令周期是完成一条指令所需全过程；时钟周期是基本节拍。多周期实现中一条指令可占多个时钟；流水线中多条指令的周期相互重叠，不能由CPI直接推断单条延迟。

## 4.2 数据通路基本结构和定时

组合逻辑依据当前输入产生输出，寄存器等状态元件在规定时刻锁存值。时钟周期要容纳关键路径延迟、寄存器建立时间等；缩短时钟周期需改变路径或流水分段，不能让信号尚未稳定就锁存。

单总线结构共享传送通路，硬件省，但同一时刻通常只允许一个源驱动总线，复杂操作需要多个节拍。多总线或专用通路允许更多并行传送，代价是更多连线与选择控制。多路选择器选数据来源，写使能决定目的寄存器是否更新。

单周期实现让每条指令在一个长周期完成，周期由最慢指令决定；多周期实现分阶段复用硬件，周期可缩短但CPI增加。性能应比较“周期×周期数”，不能只比较CPI。

## 4.3 数据通路工作原理

指令语义可以进一步分解为数据通路上的微操作。确定操作数来源、所经运算部件和结果目的地后，才能判断需要哪些选择信号和写使能。以下微操作描述基本过程；其中哪些操作能够并行，取决于具体电路的资源和连接方式。

以使用MAR和MDR的取指过程为例，CPU先执行MAR←PC，将取指地址送到存储器，并发出读请求。数据返回后执行MDR←M[MAR]，再由IR←MDR保存指令。顺序执行所需的PC更新为PC←PC+指令长度。实际实现可以将其中部分操作合并或并行安排。

| MIPS指令 | 核心数据流 | 关键写操作 |
| --- | --- | --- |
| add rd,rs,rt | 寄存器两读口→ALU加→结果选择器 | 写rd |
| lw rt,imm(rs) | 基址+符号扩展位移→数据存储器读 | 主存数据写rt |
| sw rt,imm(rs) | 基址+位移→地址端，R[rt]→数据端 | 写数据存储器，无寄存器写回 |
| beq rs,rt,imm | 比较两寄存器，形成分支目标 | 条件成立时更新PC |

所有指令都有取指操作；“sw不读存储器”通常指不读**数据**存储器，不能忘记取指访问。IR等寄存器是否需要独立设置也与实现方式有关。

## 4.4 流水线执行

教材先给出一般分段示意，再给MIPS五段：IF取指、ID译码/读寄存器、EX运算/算地址、MEM数据访存、WB写回。流水段间寄存器传递数据、目的寄存器号和控制信息。

R型运算的MEM段为空；sw无寄存器写回；简单流水线仍保留对应位置，以维持统一流动。某段无有效工作不代表其他指令可以随意跨段。

理想k段流水线，各段周期τ，n条指令：

$$T_{pipe}=(k+n-1)\tau，\quad TP=\frac{n}{(k+n-1)\tau}$$

若串行每条需kτ，加速比为nk/(k+n−1)，n很大时趋近k。存在s个额外停顿周期则时间为(k+n−1+s)τ。各段延迟不等时，τ至少由最长段与寄存器开销共同决定。

例：5段、τ=2 ns，10条无冲突指令共14周期=28 ns，吞吐率10/28 ns≈3.57×10⁸条/s。同样每条串行10 ns时总100 ns，加速约3.57。稳态理想CPI≈1，但单条经历五段，延迟约10 ns。

## 4.5 控制器设计

硬连线控制器将操作码、状态、节拍等输入经逻辑电路转换为控制信号。设计时分析指令 → 列微操作与时序 → 确定控制信号 → 建立逻辑关系并实现。通常速度快，复杂指令的逻辑设计和修改较困难。

微程序控制器将控制步骤存入控制存储器，由微地址顺序及转移逻辑读取微指令，逐步发出微命令。机器指令是程序员使用的操作；微程序是实现该指令的一串微指令；微命令是某项基本控制动作。控制存储器不等于存放用户程序的主存。

水平型微指令用较直接的控制位表达并行微命令，字较宽；垂直型编码较集中，需译码、字较短。微程序控制较规整、易修改，但控制存储访问带来时间开销。

## 4.6 流水线冒险

| 类型 | 发生原因 | 处理方法 |
| --- | --- | --- |
| 结构冒险 | 同周期争同一资源，如统一单端口存储器取指与取数 | 增加/分离资源或停顿 |
| 数据冒险 | 需要的结果尚未可用 | 转发、停顿、编译调度 |
| 控制冒险 | 分支方向或目标未确定 | 停顿、预测，错误时冲刷 |

数据相关是程序的数据依赖；是否形成冒险取决于流水线时序。基本顺序五段线重点看先写后读RAW。转发把尚未写回的结果送给使用者，减少等待，但不能让结果早于实际生成时间出现。

经典load-use：`lw $t0,0($s0)`紧接`add $t1,$t0,$t2`，load到MEM末才读出数据，而后继EX已需要它，常需停顿1周期再转发。具体停顿数以题设转发路径、读写时序为准。

流水线时空图通常以行为指令、列为时钟周期。在理想的IF至WB排列基础上，结合资源占用、结果可用时刻和分支确定阶段，可以找出需要停顿或冲刷的位置。同一种数据相关在不同转发路径和读写时序下，可能产生不同的停顿周期数。

## 4.7 高级流水线

基本流水线通过重叠不同指令的执行阶段提高吞吐率。进一步提高性能，可以增加流水段数，或在一个周期内发射多条指令。前者称为超流水线，较细的分段有助于缩短周期，但也会增加流水寄存器开销，并可能增大分支预测失败的代价。后者属于多发射，其效果受程序中指令级并行（ILP）的限制，即有多少操作能够在满足依赖关系的前提下并行处理。

IPC表示每周期完成的指令数，等于完成指令数除以周期数；多发射处理器的IPC可以大于1。在相同统计范围内，CPI与IPC互为倒数。

静态多发射由编译器安排并行发射，VLIW把多个操作组织在长指令中；动态多发射由硬件运行时决定，超标量是典型形式。动态调度和乱序执行允许就绪指令先执行，但仍需保证体系结构可见结果符合程序语义，通常通过有序提交等机制实现。

## 4.8 异常和中断

内部异常通常与当前指令同步，如非法指令、除零、缺页；外部中断来自设备、时钟等，与当前指令异步。两者都可能要求保存返回信息、转到处理程序、处理后恢复。

- 故障fault：通常可修复并重新执行故障指令，如缺页；保存位置要能支持重执行。
- 陷阱trap：在指令完成后报告，常返回后继指令，如某些调试/系统服务机制。
- 终止abort：严重错误，通常不能按原程序正常恢复。

硬件负责识别事件、保存必要返回状态并转入入口；处理程序完成具体处理与更完整的现场保护。保存断点只保存恢复所需的指令位置，保存现场还包括寄存器、状态等。不同异常返回点不同，不能一律写PC+4。

## 自测题

1. 五段线100条、停顿6周期共几周期？
2. 转发能否消灭所有RAW冒险？
3. 微指令是普通应用程序中的机器指令吗？
4. 缺页和键盘中断分别是什么？
5. 流水线是否必然缩短单条指令延迟？

### 参考答案

1. 5+100−1+6=110。
2. 不能，需看结果何时可用。
3. 不是，是控制层实现步骤。
4. 内部异常、外部中断。
5. 不能保证，主要提高连续指令吞吐率。
