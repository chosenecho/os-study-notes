# R9：阅读体验复审与细化

日期：2026-11-03。范围为两门课 12 章笔记、两份课程 README 和两份共用速查表，共 16 份 Markdown 源文件。目标是让读者按自然顺序理解概念、步骤和条件，同时保留教材术语、计算结果、来源标注及现有站点结构。

## 审读发现与处理

| 发现 | 例子 | 处理 |
| --- | --- | --- |
| 多个操作步骤挤在一句话或一段中，读者难以回看中间状态 | C 程序预处理至装入、系统调用链、磁盘 I/O 路径、PV 建模、DMA 与中断响应 | 按执行顺序拆为短段或编号步骤，保留原有步骤、状态和责任主体 |
| 一个段落同时讲定义、计算和例外条件 | EAT 缺页公式、除法恢复步骤、显示帧数据量、Cache 地址访问 | 先定义量和条件，再列公式或步骤，最后给结果及解释 |
| 口语比喻替代了技术对象 | “干等盘片”“跑到底”“栽跟头”“住在页框”“塞进目录项”“顺藤摸瓜” | 改成等待旋转延迟、非抢占运行、页到页框映射、目录项保存簇号、按表项查找等明确表述 |
| 术语或记号首次出现时不清楚它代表地址、内容还是状态 | 有效地址与操作数、页框编号与物理字节地址、CPI 与执行时间 | 在自编小例和过渡句中补清各量的含义；不改教材习题解答 |
| 表格中的口语评价不便复习时精确引用 | “大头”“白耗”“赖着不走”“CPU 100% 陪着空转” | 换成开销、未利用资源、历史访问计数及持续占用 CPU 等可核对表述 |
| 术语或句子重复，但后半句没有新增信息 | 组成原理第 1 章性能段重复说明 CPU 时间不等于总运行时间 | 保留定义处说明，在末段只保留算法、编译器、ISA 与硬件对 IC/CPI/T 的影响 |
| 图表或 Markdown 层级不清 | 组成原理第 4 章异常分类列表缩进错误 | 修正嵌套列表层级，使故障、陷阱、终止明确隶属内部异常 |
| 用词错误 | 组成原理第 5 章 SRAM/DRAM 表头“典型岗位” | 改为“典型用途” |
| 单位口径可导致公式被误读 | 64 KB 与 128 MB/s 的磁盘传输算例 | 明确按 1024 进位，保留正确的约 0.488 ms 和 12.655 ms；未登记为数值勘误 |

## 保留原则

- 两门课程的能力层次、考纲条目、页框/Cache 等模型条件及教材题目来源均保留。
- 导读中的章节主线、易错点表中的正确做法，以及正文与章末复习之间的少量重复属于不同阅读场景的导航，不作为冗余删除。
- 高频概念如定义、公式和易混条件仍在需要它们的章节出现；不为降低重复率而强迫读者跨章回查。
- 没有足够证据说明会妨碍理解的专业密集段落保持原样，例如完整协议/算法规则、历史模型边界和需逐项对照的寄存器字段。
